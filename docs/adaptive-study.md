# 按主题取证的视频学习通道

本通道用于已有完整转录、来源截图和 `input-manifest.json` 的 Codex 学习资料。使用 GPT-6.1 Sol、medium、标准速度；不改写原始视频、转录、已审阅笔记或正在运行的 Ollama 任务。

## 处理方式

1. 合并相邻 ASR 短句的时间标记，保留全部讲解文本与原始转录，不做提前删句摘要。
2. 从完整讲解建立知识主题和必要的原图取证请求，不按固定四分钟写长篇分段笔记。
3. 读取所需原图，按请求大小分批生成去重的证据卡。每批最多十二张是上传保护，不是每个视频的图片上限。
4. 并行生成主题笔记与视觉缺口清单。查漏读取全部候选截图的缩略索引；小字、参数和精细颜色必须回到原图确认。
5. 自动按合法索引补取缺口原图，保留逐项核验结果。未解决的核心问题不能隐藏；最终由审阅者对照完整讲解、原图和验收清单修订笔记。

RGB 与局部区域比较用来记录重复候选和变化原因。屏幕缩放、平移和试调会产生大量变化，因此这个检测不直接决定哪些画面可永久忽略。全部来源候选仍进入可回查索引。不能把候选帧全覆盖称为逐帧观看完整视频。

主笔记只保留知识内容及必要来源。长篇覆盖表、参数查证、错误转录和局部疑点保存为审阅材料，不拼进正文。此通道不生成最终 UI Skill。

## 使用

在项目虚拟环境中：

```sh
.venv/bin/python -m video_tutor study-clip \
  learning/batches/batch-001/ai-assisted-icons-sol61 \
  learning/benchmarks/new-clip \
  --start-seconds 6960 --end-seconds 8160
```

当前已验证的单次范围最多二十分钟。更长课程需按来源片段学习后，再做跨片段主题综合；此命令不会自动生成整课最终成品。输出目录必须独立，缓存输入发生变化会拒绝复用，避免把旧结果当新结果。

`generated_awaiting_source_review` 代表模型处理结束，仍需审阅；不能自动升级为已审阅。补查资料在 `targeted-evidence-repair-*-observations.md`。修订主笔记时保留生成原稿和审阅记录。

## 对照测试与计量

`scripts/benchmark_study.py` 使用第二课 116:00–136:00 的相同来源转录、画面、模型、思考强度和服务档位，比较旧固定窗口流程与新主题流程。两组并发上限均为二。

- 原始每次调用事件与用量保留在 `calls/`，失败尝试不应抹除。
- `input_tokens` 已包含 `cached_input_tokens`；推理输出是输出的子项，不重复相加。
- tokens 只能作为模型用量指标，不能按比例等同于 ChatGPT 订阅额度。账号百分比是共享且取整的快照。
- 总耗时必须包含补图核验；既有转录、抽帧与独立审阅的耗时另列。一次测试不构成稳定的速度保证。
- 开发调参试验与正式对照分开报告，调参消耗仍保留。缓存恢复时当前墙钟时间不能作为一次完整新运行时间。
