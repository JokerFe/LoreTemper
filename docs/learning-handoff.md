# 学习到 Skill：交接、去向与分批补充

## 产物留存

每个新建网页学习任务完成后，按视频资产、任务、文档版本和内容指纹建立不可覆盖的快照。主笔记始终为独立 HTML/Markdown；详细操作、转写、截图、原音频分块、知识清单、模型提示/回执、检查与修订记录独立保存，不拼入主总结。数据库中的来源、任务、文档版本、检查点和事件也导出到快照，复用其他任务的检查点和图片同时保存副本。

所有快照有逐文件 SHA256 清单。重试复用同一快照前检查指纹；发现笔记或文件被改动会停止交接，要求建立新任务，不能静默改写旧证据。原视频仍在来源位置，清单保存其身份与指纹。

`learning-library/index.html` 是按笔记输出目录持续追加的汇总入口。每份索引记录并显示所属笔记目录，网页工作流对应 `<输出目录>/notes`；不同目录不得混入同一索引。标题、完整主笔记正文可搜索；批次筛选包含该批新笔记及显式纳入的历史笔记。每条结果能打开完整图文笔记、Markdown、知识清单与全文件清单。目录可离线浏览，不依赖数据库服务或网络。新流程条目显示“待来源审阅”；显式收录的历史笔记显示原审阅状态，不会把模型检查成功写成人工审阅通过。

## 学习到 Skill 的交接清单

本批全部视频成功后，冻结 `handoff.json` 和 `handoff-manifest.json`，另提供可读 Markdown。记录每份笔记的来源身份、位置、SHA256、审阅状态、知识清单、全部快照文件以及缺项。Skill 阶段读取笔记与知识清单文本，保留图片及详细查证，**不会在提炼时再次识别图片**。

交接前检查每个快照及笔记指纹。串联视频缺少知识清单时不能宣称去向已核对，会停止并保留材料。独立输入的普通 Markdown 若不含知识清单，则显式列为“缺少知识清单”；不据此宣称覆盖了原视频的所有知识。

## 知识点去向

知识 ID 包含视频、任务、清单位置与局部 ID 的命名空间，多个视频出现相同局部 ID 不会互相覆盖。逐项对照同来源笔记和候选规则，分组、分窗口读取完整内容，不以只取前几条的方式丢掉内容。模型返回的笔记引文必须在当前来源窗口中出现，规则 ID 必须属于当前来源且实际存在；无效结果允许一次修复，全部尝试保留。

| 去向 | 含义 | 后续处理 |
| --- | --- | --- |
| 进入规则 | 在笔记中找到对应内容，并关联候选规则 | 可追到能力指南、条件记录及来源；仍需独立复核 |
| 保留在笔记 | 找到原笔记内容，但未关联规则 | 保留案例、背景等知识，不能强行升格为通用规则 |
| 需要复核 | 当前自动映射未找到可靠笔记依据 | 保留原知识与映射原因，回查讲解、图片和笔记 |

输出同时含机器可读 JSON 与可搜索 HTML。去向表体现可追溯性，不是课程知识完整性的独立证明；知识清单自身的遗漏仍须通过来源审阅发现。

## 后续批次补充

1. 继续使用同一输出目录，填写新批次名称并选择新视频。
2. 仅积累资料时选择“视频学习”；需要本批综合时选择“学习并生成 Skill”。
3. 希望综合旧知识时勾选“补充到已有学习内容”，预览历史来源后提交。该选项仅在串联模式生效。
4. 新笔记与旧笔记一起进入新一轮综合，重复观点可融合，新条件和冲突须保留。一个视频的新版仅替换本次综合所使用的输入，历史版本仍在资料库。
5. 每次生成使用独立流程目录，旧 Skill 不覆盖、不安装、不自动发布。阶段素材齐备与正式发布继续遵循项目约定。

新流程自动追加收录。已有 `learning/catalog.json` 中的已完成笔记可以显式补录：

```bash
uv run python -m video_tutor.import_learning --catalog learning/catalog.json --notes-directory "./learning/batches" --output "./learning/batches"
```

先限定 `--notes-directory` 指定的笔记目录，只收录该目录及其子目录中的主笔记，再读取每门课程的实际 `status.json`，要求学习完成、主笔记和 HTML 均存在，不以目录中旧的流水线状态快照判断完成。原批次 ID 和名称保留，空批次不收录；与现有流程批次 ID 冲突时停止。完整正文支持搜索，历史批次按原顺序展示，批内按课程标题数字排序。

每篇保存 Markdown、原 HTML、完成记录及已有审阅／报告副本和指纹，阅读副本仅增加指向原目录的链接基址。图片、详细查证、素材包与视频继续保留在原位置；“视频来源与审阅记录”可以回查。缺失的原视频会在来源记录中标明，不伪造可用性。不要只移动汇总 HTML：历史笔记的阅读还依赖原学习目录与相对路径。

同一来源与文件指纹重复导入会复用条目，更新会新建版本并保留旧版；导入前另存目录备份。原笔记与原审阅状态不改写。历史条目不伪造新版知识清单，后续若选入综合会明确记录清单缺项，不能据此宣称已核对所有知识点去向。同一笔记目录内可持续分批追加；不同笔记目录不能仅因指定同一 `--output` 而混合。已有混合目录的旧索引会阻止补录、生成和历史笔记复用，须先备份并按目录拆分；拆分只调整索引，原笔记、来源和旧快照保留。

## 失败与恢复

部分视频完成、其他视频失败时，已完成笔记先收录。生成失败时复制已有交接与模型尝试到批次过程目录。修复后重试沿用冻结输入和模型，已有调用缓存按提示指纹复用；旧失败回执仍保存。新增课程或修改笔记需要创建新流程。

## 验证方式

自动化测试覆盖两视频首批、补充视频第二批、旧文件不变、版本独立、指纹篡改拦截、失败留存与重试、知识来源隔离。测试模型响应明确为模拟。

真实链路脚本使用隔离数据库与自行合成的三段有声教学视频，按“2 + 1”两批执行生产媒体处理、ASR、模型学习、交接和 Skill 生成，检查各批来源数量、知识清单去向数量与旧文件指纹。它不操作当前课程队列，不安装测试 Skill。macOS 上需要本机 Codex 登录、Whisper 模型、FFmpeg 和 `say`：

```bash
uv run python scripts/verify_combined_pipeline.py --workspace work/combined-chain-validation
```

脚本会产生真实模型调用和本地计算；保留所有输入与结果。同一路径再次运行可恢复冻结任务与调用缓存。若修改了生成提示或处理规则，应使用新的验证目录；旧调用指纹不允许被改写。该短片验证只能证明串联与保留机制，不能证明真实长课程的知识质量、正式 Skill 效果或耗时。
