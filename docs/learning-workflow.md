# 分批视频学习与最终 Skill 生成流程

## 用户目标与当前阶段

用户会分批提供多个 UI 课程视频。目标是在持续学习、记录与跨课程综合后，形成帮助 AI 设计、开发和改善页面美感的 Skill。各视频可能只覆盖某个局部方向，不能用单一课程代表完整 UI 方法。

当前阶段为已发布 Skill 的维护与后续素材学习。2026-10-20 用户明确确认以第 1—27 课生成并安装 `joker-ui`，名称和实现方案已确认；本次综合的交付记录见 `learning/skills/joker-ui-installation.json`，验证见 `learning/skills/joker-ui-validation/report.md`。该授权只覆盖本阶段 27 课，不表示未来素材已全部提供完。

历史阶段记录：2026-10-15 过早建立的 `ui-visual-craft` 已从正式技能目录撤下，原文件完整存放于 `learning/archive/ui-visual-craft-premature-draft-20261015/`，入口改名为 `SKILL.draft.md`。其中未由课程支持的页面延伸方法不能反过来充当课程证据。

## 每批视频的处理

1. 在 `learning/catalog.json` 登记批次、来源文件、资产 ID、处理任务 ID、时长和文件指纹。发现重复内容时引用已有资料，保留来源关系。
2. 运行完整讲解转写与代表性关键画面分析。用户选择优先课程要点、设计方法和关键参数，减少重复画面；短暂操作可能遗漏。疑似遗漏的重要步骤或参数，应回看对应片段并补充截图。
3. 每个视频形成独立的内容总结，按知识主题组织，说明教了什么、为什么有效、如何判断、何时以及如何应用。不设固定字数或截图数量，完整保留核心思想、判断依据、关键方法、适用条件、必要案例和影响实践的例外；篇幅由讲清知识所需决定。合并重复讲解，删除无关操作，不能为精简而遗漏重点，也不能只剩抽象口号。选择能够解释方法或前后差异的截图，数量随内容需要。不要逐字转述、流水记录每次操作，也不要把所有章节和分段拼进主笔记。影响理解或复用的关键步骤与参数进入总结，说明对象与适用条件；无关点击、临时数值、完整转录、章节和分段记录保存在独立查证材料，主笔记末尾提供入口。关键结论通过代表性时间戳、截图或审阅记录保持可追溯；保留素材名称及来源，未提供的素材标记“尚未取得”。交付前对照已审阅知识点检查覆盖，发现核心内容缺失就补回，不以字数作为完成标准。
4. 程序生成文档与人工/助手审阅分开记录。`succeeded` 只表示处理完成，不表示结论已核对。重要、模糊或与其他课程冲突的内容需回查讲解与画面。
5. 每批完成后交代哪些视频已学习、生成了哪些笔记和截图、覆盖什么主题、有哪些疑点。未完成的课程保持明确状态。

## 跨视频积累与修正

以主题组织综合索引，如图标、布局、字体、色彩、组件、动效和设计流程。主题覆盖由实际内容决定，不能因为目录里列了主题就声称已经学会。

一条候选规则应包含：具体观点、来源视频与时间戳、相关截图或素材、适用场景、例外、相关支持或相反证据，以及审阅状态。单来源规则可以保存，但标记其范围和证据不足，不自动升格成通用规范。

新视频到来时，对照旧笔记：合并重复知识，补充适用条件，保留冲突及上下文，必要时修正旧结论。不能以“新课程”为由直接覆盖旧规则，也不能为追求统一而抹掉不同产品或风格的差异。

不要把课程示例数值、老师个人偏好、助手推断或模型误读写成通用定律。原始字幕与截图保留，校正和解释在整理笔记中记录，不无痕篡改来源。

## 最终生成 Skill

当用户表示本阶段视频已提供完、可以进行综合时，读取所有批次中已审阅的笔记、截图和可用素材，再生成 Skill。处理队列暂时为空不等于用户已经停止提供视频。

最终 Skill 提炼可执行的设计判断、实施方法和检查方式；详细证据、案例、反例及适用边界放入引用资料。保留来源索引，不把所有笔记简单拼接成一个巨大的入口文件。

用有代表性的页面设计、页面开发和页面审查请求检验 Skill 是否能改善实际结果，再交付正式版本。后续新增批次仍先学习、记录、对照，再据新证据修订 Skill，而不是逐视频直接覆盖正式技能。

## 文件与状态约定

### Codex 主题取证通道

2026-10-16 新增可复用的 `study-clip` 入口，使用完整讲解先建主题、原图证据卡、全部候选画面的查漏索引，以及按缺口补图核验。详见 [处理方式与计量约定](adaptive-study.md)。生成与审阅仍分开，模型查漏无报错不等于关键证据已经全部确认。主笔记不拼入逐项审查表；实验结果与原课程笔记分开保存。

- `learning/catalog.json`：批次、资产与笔记索引；状态含更新时间，只是快照。
- `learning/batches/`：逐视频整理笔记及审阅记录，未完成内容标注 partial。
- `notes.md` 与其 HTML 为默认内容总结；详细记录和截图单独积累，重新导出不能用分段拼接结果覆盖总结。2026-10-15 用户明确要求提炼内容并保留核心思想与重点，不设固定字数；不能把这一要求理解为越短越好。
- `data/assets/<asset_id>/runs/<run_id>/`：流水线字幕检查点、截图、观察结果、图文笔记与导出产物。具体产物存在后再宣称已生成。
- `learning/archive/`：撤回草稿等历史材料，不作为正式学习成果。

本文件保存工作约定，不是定时任务，也不代表已经实现无人值守的跨视频审阅或自动 Skill 发布。当前后台分析继续运行；每次处理新批次或整理结果时遵循上述流程。

### 页面中的独立生成与串联模式

2026-10-19 用户要求视频学习和笔记生成Skill可以分别运行或串联运行。页面中的显式“生成Skill”或“学习并生成Skill”只针对本次选定资料授权进入综合；不据此推断全部课程素材已齐。生成文件保留来源、适用边界和待验证状态；来源审阅、结构校验、实际任务效果验证与安装发布分别记录。只选择视频学习时仍然积累资料，不自动生成Skill。

### 参照 Joker UI 的生成质量流程（2026-10-20）

新建页面任务使用`joker-ui-v2`。笔记增加核心知识清单、内容覆盖核对和有界修订，主总结与详细查证分开；Skill增加有条件的结构化规则、能力路由、完整覆盖映射、包内来源与链接校验。详见[生成质量流程](generation-quality.md)。本次优化生成器，不重写已发布的`joker-ui`或既有已审阅笔记。自动内容检查与实际任务效果验证保持分开，新生成产物仍保留待验证状态。

### 分批资料库与学习交接（2026-10-21）

新建网页任务按视频保留独立笔记和完整过程快照，追加到输出目录的 `learning-library/index.html`，支持正文搜索和批次筛选。串联生成前冻结交接清单，生成后逐项记录知识进入规则、保留在笔记或需要复核的去向。后续批次可显式纳入同一输出目录的历史笔记进行新一轮综合，旧笔记和旧 Skill 保留。详见[交接、知识去向与分批补充](learning-handoff.md)。此机制不自动回填旧目录、不替代来源审阅，也不授权安装或发布新 Skill。

### 汇总的目录边界（2026-10-22）

用户指定的笔记输出目录是汇总边界。同一目录中的多个视频可分批追加，按原批次查看；不同笔记输出目录各自生成汇总，不能混入同一 HTML 或通过“历史笔记”隐式混用。历史补录也必须限定笔记目录，汇总页面显示所属路径；`--output` 仅表示汇总存放位置，不能把其他笔记目录并入。当前历史课程目录 `learning/batches` 与验证示例的笔记目录已分别建索引。
