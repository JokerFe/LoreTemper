# 笔记与 Skill 生成质量流程

2026-10-20 参照已发布的 `joker-ui` 的方法结构升级网页生成流程。依据包括任务路由、能力指南、条件规则、来源/图片索引、规则覆盖映射，以及将结构检查、自动内容检查与实际任务验证分别记录。参考结构，不复制其27课内容、315条规则或固定能力数量作为新任务的默认结果。现有正式Skill、课程原笔记与旧任务配置不被此改动覆盖。

## 笔记总结

完整转录与已核对的原图证据先进入主题总结，再建立核心知识清单，逐项检查思想、判断依据、方法、条件、必要案例与关键参数的保留情况。遗漏、无依据结论、未解释的冲突触发一次有来源的修订与复核；仍未解决则报错并保留原稿与报告，不声称完成审阅。无字数、主题数或截图数目标。模型的知识清单与覆盖检查不是独立来源审阅。

本地模型采用完整来源的有界分块和主题融合，不能静默截断来源。输入超预算或融合不收敛时明确报错并保留资料。本地主题总结使用32K上下文请求，受模型实际能力约束。主总结保存在`document.md`/HTML中；完整操作、证据索引与转录保存在`detailed-records.md`、SRT和JSON；页面通过“详细查证”单独查看操作。`quality/`保存知识清单、覆盖记录与修订结果，不拼进主笔记。

所有生成的图片引用必须指向实际选取的本地图片；外链、越界路径和未选图片不能作为已审阅证据。

## Skill 生成

1. 确认本次选定笔记，冻结指纹，保留原笔记和可取得的引用图片。重复内容不增加独立来源数；已知同一视频的多份笔记保留共同来源标识。目录中的审阅状态作为继承记录，不能代替本次复核。
2. 按来源提炼结构化候选规则：观点、判断依据、方法、条件、例外、证据类型、原文短句和位置。原文短句必须出现在该段来源，时间戳不能编造。无可提炼规则的来源记录原因，不静默跳过。
3. 建立按真实问题选择的能力路由，映射必须逐条覆盖所有候选规则且每条一次。能力与数量由本次材料决定。
4. 每项能力融合方法和不同条件，保留支持、分支和冲突。独立条件库完整保存每条规则，能力指南另做逐项自动内容检查；修订一次仍有实质缺口就停止并保留报告。
5. 编写渐进读取的Skill入口：任务→能力指南→条件库→原始证据。入口不加载或拼接所有课笔记，也不能替用户覆盖品牌、功能、框架、技术栈等范围。
6. 校验frontmatter、包内文件、来源哈希、能力路由、规则映射与规则锚点。提供新设计、既有成果优化、实施/评审的待执行验证计划；不把该计划说成实际验证已经通过。生成不自动安装或发布。

典型包结构：

```
SKILL.md
references/
  capabilities/<能力>.md        # 问题路由与融合指南
  rules/<能力>.md               # 每条规则的条件、例外与原文依据
  sources/source-NNN/notes.md    # 原始笔记与可取得的相对路径图片
  coverage/rules.json           # 规则→能力→条件→来源的完整映射
  coverage/source-files.json    # 原始/打包指纹与审阅状态
  coverage/generation-report.json
  coverage/validation-plan.md
```

短结构化模型响应同样要通过语义数据结构校验；无效输出允许一次修复，全部尝试留账。已创建旧任务继续使用其冻结版本，新建网页任务使用`joker-ui-v2`。新增覆盖与修订会增加调用量，页面原有样本仅是基础流程历史消耗，不是新版总价保证。

## 本次验证

后端全套74项测试通过，页面7项测试通过，构建与修改模块静态检查通过。新增用明确模拟的模型输出验证：有界修订后仍遗漏时停止；引用原文和时间校验；规则完整映射、相对路径和锚点校验；来源图片打包；本地总结与独立查证材料；页面主总结不再拼入全部步骤。测试不等同于独立模型效果对照或重新审阅27课，后续真实生成仍逐次保留用量与质量记录。
